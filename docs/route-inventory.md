## Non-page route boundaries and dispatch rules

- `apps/web/proxy.ts` applies to application routes and `/api`/`/trpc`; excludes `_next` and listed static extensions, and explicitly includes `/api` and `/trpc`. It normalizes trailing slashes with 308, checks `WORKOS_COOKIE_PASSWORD` length, resolves the callback host, runs AuthKit middleware, sets the tenant hint cookie, and applies security headers.
- `apps/web/next.config.ts` declares no redirects or rewrites. It adds response headers globally.
- Root `app/layout.tsx` wraps all route groups. `(panels)/layout.tsx` mounts the Convex client and `AppShell`; `/platform/*` adds the platform role guard; `/dashboard/*` adds the dashboard role guard and current-workspace lookup; tenant feature layouts use `TenantPanelLayout`.
- `convex/http.ts` declares `POST /workos/webhook`, verifies `WorkOS-Signature`, rejects missing configuration with 503 and invalid signatures with 401, and queues verified deliveries. No other `http.route()` is declared in this checkout. The auth README also mentions `/collector/ingest`, but no handler exists in `convex/http.ts`.
- `app/error.tsx` and `app/global-error.tsx` provide safe retry pages. There is no `app/not-found.tsx`; unmatched authenticated routes use the framework default. `dashboard/forbidden.tsx` is a segment boundary, not a URL.
- `apps/web/subscriber-portal/` contains no route entry under `apps/web/app`; no subscriber self-service URL is implemented in this App Router tree. Status pages likewise have no route entry.
